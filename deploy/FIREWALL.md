# UFW с сохранением входа по логину и паролю

Для текущего VPS `134.0.113.203` разработчик подтвердил 18.09.2026: UFW включён,
входящие по умолчанию запрещены, исходящие разрешены, TCP 22/80/443 разрешены
для IPv4 и IPv6. Вход по логину и паролю сохраняется. Повторять настройку ниже
не требуется. Новый вход по SSH с паролем проверен разработчиком успешно;
доступность обоих сайтов после включения подтверждена внешними HTTP-проверками
после выпуска исправлений 18.09.2026.

Ниже сохранён выполненный порядок настройки. Команды не меняют SSH,
пользователей, пароли, сайт, SMTP или платёжную систему.

Выполнять в уже открытом терминале **VPS в Remote Explorer**, по одной команде.
При ошибке остановиться и передать её текст. Текущий сеанс оставить открытым;
доступ к консоли VPS в REG.RU сохранить как резервный способ входа.

Сначала добавить разрешения в начало правил, чтобы старое запрещающее правило
не перекрыло доступ. Не выполнять `ufw reset`:

```bash
sudo ufw insert 1 allow 22/tcp
sudo ufw insert 2 allow 80/tcp
sudo ufw insert 3 allow 443/tcp
sudo ufw default deny incoming
sudo ufw default allow outgoing
```

Затем включить firewall:

```bash
sudo ufw enable
```

На `Proceed with operation (y|n)?` ответить `y`. Разрешения SSH и сайта уже
должны быть добавлены предыдущими командами без ошибок.

```bash
sudo ufw status verbose
```

Ожидается `Status: active`, входящие по умолчанию запрещены, исходящие разрешены,
22/tcp, 80/tcp, 443/tcp разрешены. При включённом IPv6 также видны правила `(v6)`.
Существующие правила не удаляются; итоговый список проверить целиком.
SMTP REG.RU работает через исходящее подключение на 465, открывать входящий 465
или 5432 для PostgreSQL не требуется.

Открыть **второе новое** подключение Remote Explorer к тому же IP с прежним
логином и паролем и обе страницы сайта. Старое подключение закрывать только
после успешной проверки нового. Если новое подключение или сайт перестали
работать, через оставленный сеанс либо консоль REG.RU откатить включение:

```bash
sudo ufw disable
```

Для продолжения аудита передать вывод `ufw status verbose` и результат проверки
нового входа и сайтов. Далее — выпуск исправлений приложения, проверка почты
и резервного восстановления. Ограничение подбора паролей можно настроить отдельно,
сохраняя выбранный пользователем способ входа.

Документация: [UFW в Ubuntu](https://manpages.ubuntu.com/manpages/noble/man8/ufw.8.html).
