## Проверка продления на VPS

```bash
sudo nginx -t
sudo certbot renew --cert-name dari-sinergii.ru --dry-run --run-deploy-hooks --non-interactive
systemctl show certbot.timer --no-pager -p ActiveState -p UnitFileState -p NextElapseUSecRealtime
```

Ожидаются успешная тестовая выдача и включённый активный таймер с будущим запуском.
`--dry-run` использует тестовый выпуск; тестовый сертификат не заменяет рабочий.
`--run-deploy-hooks` дополнительно запускает сохранённый deploy-hook с рабочим
сертификатом. Такой hook может проверить и перечитать конфигурацию Nginx.
Если Certbot завершится ошибкой, сохранить её текст, не выпускать новый
сертификат вручную и не менять DNS вслепую.

[Документация Certbot](https://eff-certbot.readthedocs.io/en/stable/man/certbot.html).

## Политика HSTS

В новом HTTPS-релизе область задаёт `HSTS_INCLUDE_SUBDOMAINS`, по умолчанию
`false`. Разработчик подтвердил установку; публичные ответы подтверждают
узкую политику. [Порядок установки с откатом](INSTALL-HTTPS-20260921.md)
сохранён для справки; повторная установка сейчас не требуется.

Установлены и подтверждены по публичному заголовку начальный срок и область:

```dotenv
HSTS_SECONDS=300
HSTS_INCLUDE_SUBDOMAINS=false
```

Подтверждённый заголовок на HTTPS-ответах главной и магазина:
`Strict-Transport-Security: max-age=300`. Без `includeSubDomains` и `preload`.
Так каждый посещённый хост получает свою политику, без распространения на
непроверенные почтовые или служебные поддомены. После периода наблюдения срок
можно повышать отдельно; годовой срок автоматически не включать.

При такой области действия `check --deploy` выдаёт `security.W005` и
`security.W021` про выключенные includeSubDomains и preload. Это ожидаемые
предупреждения выбранной политики; настройки не менять лишь для их удаления.

Отключение: вернуть `HSTS_SECONDS=0`, перезапустить приложение. Браузер,
получивший предыдущий заголовок, может хранить его до окончания прежнего срока;
остановка выдачи заголовка не очищает уже сохранённую политику мгновенно.

[Область HSTS в Django](https://docs.djangoproject.com/en/5.2/ref/settings/#secure-hsts-include-subdomains).

## Внешний мониторинг

**Отложен по решению разработчика от 21 сентября.** Аккаунт, мониторы и получатель
не настроены. Инструкция ниже сохранена на будущее; она не является текущим
следующим шагом. Настройка SSL и короткой HSTS-политики завершена отдельно.

Подходящий вариант — [HetrixTools](https://hetrixtools.com/). На дату проверки
бесплатный план содержит 15 мониторов с интервалом 1 минута и контролем SSL.
Условие бесплатного плана: вход в кабинет не реже одного раза в 90 дней.
Ответственному следует поставить напоминание; платный план снимает это условие.
[Тариф и условие активности](https://hetrixtools.com/pricing/uptime-monitor/).

Зарегистрировать кабинет на клиента и подтвердить почту. В Contact Lists →
Add New Contact List добавить согласованный адрес аварийных уведомлений.
Нажать Send test notification, убедиться, что письмо пришло, сохранить список.
Затем назначить его каждому монитору. Можно использовать Default Contact,
если адрес регистрации принадлежит человеку, который будет реагировать на сбои.
Это отдельный получатель сообщений о сбоях, настройки писем о заказах в Django
не меняются. Получатель и кабинет в текущей сессии пока не подтверждены.
[Создание списка и тест уведомления](https://docs.hetrixtools.com/create-a-contact-list/).

Открыть Uptime Monitors → Add Monitor, выбрать Website/Website Monitor.
Создать четыре HTTPS-монитора, метод GET, ожидаемый код 200:

| Назначение | URL | Проверяемый текст |
| --- | --- | --- |
| Главная страница | `https://dari-sinergii.ru/` | `Дары Синергии` |
| Каталог | `https://shop.dari-sinergii.ru/` | `Каталог` |
| Приложение и БД основного домена | `https://dari-sinergii.ru/health/` | `"status": "ok"` |
| Приложение и БД магазина | `https://shop.dari-sinergii.ru/health/` | `"status": "ok"` |

`/health/` выполняет SELECT 1; ошибка БД даёт 503. Это не проверка доставки
писем, резервных копий или оформления заказа. Метод HEAD вернёт 405, поэтому
монитор должен запрашивать GET. Интервал — 1 минута. Выбрать четыре локации;
в расширенных настройках Number Of Failed Tries — 2, Number Of Failed Locations — 2,
Timeout — 15 секунд. Это начальная настройка подтверждения сбоя, чтобы единичный
сбой в одной локации не вызывал уведомление. Выбрать созданный Contact List
вместо No Contact List / No Notifications и дождаться первой успешной проверки.
[Поля формы монитора](https://docs.hetrixtools.com/add-a-website-uptime-monitor/).

В расширенных настройках включить проверку соответствия имени и действительности
сертификата. Для напоминания о сроке SSL выбрать 14 дней. Если включается
напоминание о домене, сверить отображаемую дату с REG.RU, не полагаться только
на распознавание WHOIS.

- [Проверка текста ответа](https://docs.hetrixtools.com/how-to-set-up-keyword-monitoring/).
- [Проверка TLS](https://docs.hetrixtools.com/ssl-monitoring/).
- [Напоминания о сроке SSL](https://docs.hetrixtools.com/ssl-certificate-expiration-date-monitoring/).

Проверить тестовое уведомление из кабинета и фактическое получение письма.
Рабочий сайт для теста отключать не нужно. Мониторинг считается настроенным
после создания проверок, назначения получателя и проверки доставки, а не после
составления этой памятки. Агент не создавал аккаунт и не отправлял уведомления.
