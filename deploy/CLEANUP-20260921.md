# Очистка VPS после выпуска HTTPS

Разработчик разрешил очистить ненужные файлы. Диагностика 21 сентября показала:
диск 30 ГБ, занято 7,6 ГБ (27%), свободно 21 ГБ. Срочного дефицита места нет.
Рабочая ссылка — `https-20260921`, предыдущая — `seo-20260921`.

## Конкретный план

| Объект | Размер по диагностике | Действие |
|---|---:|---|
| `/srv/dari/releases/first` | 288 МБ | Удалить после проверки отсутствия использования/локальных данных |
| `/srv/dari/releases/email-76d6352` | 288 МБ | То же |
| `/srv/dari/releases/readiness-20260918` | 235 МБ | То же |
| `/root/.cache/pip` | 22 МБ | Очистить кэш загрузок |

| Шесть старых setup/start-скриптов в `/root` | Не замерялось отдельно | Сначала проверить использование, затем сохранить и проверить закрытый архив, убрать оригиналы |

Ожидаемое освобождение — примерно 1,2 ГБ. Это оценка; фактический результат
показывается после выполнения. Журналы занимают 54 МБ — очищать их не требуется.

Рабочий и предыдущий релизы, `/srv/dari/shared`, `/srv/dari/backups`, `/etc/dari`,
конфигурационные копии, SSH, VS Code и неизвестный рабочий каталог
`/root/dari-sinergii` сохраняются. Скрипты backup/release/send_notifications
в рабочем релизе используются службами и не являются мусором.

## Выполнение

В локальном PowerShell из папки проекта:

```powershell
scp .\deploy\cleanup_vps_20260921.py .\deploy\send-client-test-email.sh root@134.0.113.203:/root/
```

На VPS:

```bash
sudo python3 /root/cleanup_vps_20260921.py --apply
```

Без `--apply` скрипт только проверяет и печатает план. Перед удалением он сверяет
current/previous, физические пути, точки монтирования, ссылки из конфигурации
и использование работающими процессами. `.env`, локальная БД, var/media/backups
в старом релизе остановят очистку для отдельного разбора.

В архив идут только неиспользуемые установочные скрипты из явного списка.
Архив сохраняется в `/root/dari-maintenance-20260921/` с закрытыми правами;
содержимое проверяется по контрольным суммам до удаления оригиналов. Если
скрипт используется конфигурацией или процессом, он остаётся на месте.

Ожидаемый итог: `FILES_CLEANED`, две строки `HEALTH_OK` и `CLEANUP_OK`.
Если появилось `CLEANUP_STOPPED`, прислать вывод: повторять блок вслепую не нужно.
Если строка FILES_CLEANED уже есть, файлы удалены, даже если последующий HTTP-тест
не прошёл. Для проверки сервиса не требуется повторная очистка.

После очистки можно отдельно выполнить
`sudo bash /root/send-client-test-email.sh` для [проверки письма](CLIENT-EMAIL-CHECK.md).
Это независимая операция, допустимая и при остановке очистки на проверках.

## Состояние

Скрипты подготовлены и переданы разработчику для запуска. Локально прошли Ruff,
проверки защищённых путей, обнаружения локальных данных, целостности архива
и отказа перезаписывать существующий архив. Реальное удаление на VPS и фактически
освобождённое место пока не подтверждены.
