# Неоплаченный заказ на VPS

Status: in progress

Запрос владельца 04.10.2026: СДЭК проверить завтра с реальным API; реальные товары
пока пропустить; сейчас проверить неоплаченный заказ. Банк пока не подключён.

Подготовлен отдельный операторский `deploy/check_unpaid_order.py` без изменения
публичного checkout и env. Временный статический способ получения создаётся
и удаляется в одной транзакции; PostgreSQL не показывает его другим соединениям.
Сохраняется один явно отмеченный DEMO-заказ с настоящим резервом и двумя письмами
в штатной очереди. Повтор run ID использует существующий заказ. Отмена выполняется
штатным `transition_order`; история заказа сохраняется. Подробности запуска и
ограничения — `docs/UNPAID-ORDER-CHECK.md`.

Локально проверяются создание через CSRF-protected checkout, идемпотентность,
серверная цена, доступ по ссылке, штатная очередь, повтор после SMTP-сбоя, отмена,
отказ для рабочего банка и реального товара, откат всей транзакции при ошибке.
Отдельная PostgreSQL-проверка подтверждает невидимость временной доставки
из другого соединения. Тесты не используют рабочую БД или настоящий SMTP.

Результаты подготовки: на SQLite 4 сценария прошли, PostgreSQL-сценарий пропущен.
Для коммита `71d8d15a384f37cf6b329425fb40d950c5ac36e2` шаг PostgreSQL and HTTP
behavior в [GitHub Actions](https://github.com/qwavezzz/daari-sinergii/actions/runs/37222873789)
завершился успешно, включая отдельное соединение для проверки изоляции доставки.
Линтер, форматирование, контрольная сумма опубликованного Python-скрипта и синтаксис
операторского Bash-блока проверены. Полный CI на момент записи ещё выполняет
браузерные сценарии. Установленный релиз VPS не менялся.

## Результат VPS: создание, резерв и очередь

Контрольная сумма установленного скрипта совпала. `created_now: false` означает
повторное использование ранее созданного заказа этого run ID, без нового заказа.
Первичный вывод `created_now: true` не предоставлен; повторный запуск не выполняет
заново проверки HTTP, предусмотренные веткой создания.

- Заказ `1dd93297…`: `status: new`, `payment: unpaid`, `test_mode: true`;
  сумма 1290.00 руб., товар DEMO-001.
- Физический остаток 24, зарезервировано 1; один активный резерв одной единицы.
- Срок резерва до `2026-10-04 18:39:45 UTC`.
- Оба уведомления `created` (customer/manager): одна попытка, `last_error` пуст,

Это подтверждает состояние заказа и принятие обоих писем SMTP. Пользователь затем
подтвердил получение письма покупателем; корпоративный ящик пока проверить не может.

другом браузере ещё не подтверждено.
