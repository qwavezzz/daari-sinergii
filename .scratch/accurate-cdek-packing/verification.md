## Исправления после скептического аудита — 02.10.2026

Реализованы:

- До восьми различных полных планов из проверенных схем; варианты отбираются по числу мест, объёму после округления до сантиметров и весу. Стоимость сравнивается по реальным ответам перевозчика, в заказ сохраняется выбранный план. Глобальный минимум среди всех возможных упаковок не обещается.
- Явный `err_result_service_empty` позволяет перейти к следующей упаковке. Ошибки авторизации, частоты запросов, сервиса, параметров, формата ответа и сети разделены. Секреты и произвольные сообщения API не выводятся.
- Общий бюджет 20 секунд начинается до получения ПВЗ и OAuth; таймаут каждого запроса ограничен оставшимся временем. Это не жёсткая отмена всех операций DNS/сокета. При окончании бюджета между запросами можно использовать уже полученную успешную цену с `packing_comparison.finished=False`.
- Проверка схем использует один загруженный набор связанных данных. Подпись зависит от подходящих корзине активных правил с подтверждением (либо явно учебных правил в sandbox), физических параметров, состава и инструкции. Переименования и посторонние правки её не сбрасывают; новые подходящие правила и отзыв подтверждений учитываются. Чтение справочника для подписи также ограничено.
- Подписывается тот же снимок, из которого построены посылки. Регрессии на переключение схем A → B → A и изменение товара между чтениями отклоняются до обращения к перевозчику.
- Проверка веса допускает только математическое расхождение округления N положительных компонентов — N − 1 граммов; фактический полный вес не заменяется. Явный `test_mode=True` не обходит рабочую среду для отдельных посылок. Учебная команда защищает товары из реальных подтверждённых схем.

- **13 браузерных сценариев прошли**: оформление СДЭК, смешанная упаковка, админские формы, подтверждение и переход к пробной оплате. - Ruff check/format для всего проекта, `git diff --check`, Django `check`, `makemigrations --check --dry-run` — успешно. Новых миграций для этих исправлений нет.
- Независимый полный перебор малых задач: 1000 случайных каталогов при дополнительной проверке оптимизатора и ещё 100 при отдельной проверке альтернатив; проверены покрытие, канонический оптимум, разнообразие и отсутствие повторяющихся физических запросов.
