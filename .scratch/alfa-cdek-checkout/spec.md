# Альфа-Банк и доставка СДЭК

Status: ready-for-agent

## Problem Statement

Магазину отказали в эквайринге без конкретной причины. Пользователь хочет сохранить демо-товары для обучения, полностью убрать прежнего платёжного провайдера и реализовать выбор ПВЗ СДЭК, серверный расчёт доставки и оплату полной суммы через Альфа-Банк.

## Solution

Покупатель выбирает СДЭК и ПВЗ через официальный виджет, получает проверенную сервером цену доставки и итог, затем переходит на защищённую платёжную страницу Альфа-Банка. Сервер подтверждает платёж независимо от возвращения браузера. Публичные документы описывают реальный процесс; незаполненные сведения не выдумываются.

## User Stories

1. Покупатель сохраняет демо-товары в корзине для обучения.
2. Покупатель выбирает перевозчика; первый подключаемый перевозчик — СДЭК.
3. Покупатель выбирает действующий ПВЗ на карте и видит адрес.
4. Покупатель видит стоимость и ориентировочный срок доставки до оплаты.
5. При изменении корзины или ПВЗ доставка пересчитывается.
6. При недоступности API покупатель видит понятную ошибку; бесплатная доставка не подставляется.
7. Получатель передаёт имя, телефон и email для заказа и чека.
8. Покупатель читает условия покупки, доставки, возврата и политику.
9. Альфа-Банк получает сохранённую сервером сумму товаров и доставки в копейках.
10. Повторное нажатие и сетевой таймаут не создают повторного списания.
11. Возвращение со страницы банка само по себе не подтверждает оплату.
12. Менеджер видит код ПВЗ, тариф, стоимость и данные получателя в заказе.
13. Владелец получает перечень настроек и фактов для реального запуска.
14. Реальная оплата не включается автоматически при сохранённых демо-товарах.

## Implementation Decisions

- Сохраняем Django, HTMX, Alpine CSP, дизайн магазина, механизм резервов и локальный трекер.
- Прямой REST API интернет-эквайринга Альфа-Банка: register.do и getOrderStatusExtended.do; серверная сверка, безопасный повтор по стабильному номеру операции, рубли/копейки без float. Уведомление банка — только повод для авторизованной сверки.
- СДЭК API v2: OAuth на сервере, проверка ПВЗ, расчёт по тарифу и упаковкам. Официальный виджет получает только публичный ключ карт и ограниченный proxy endpoint, никогда client_secret.
- Цена из браузера не принимается. Расчёт доставки связан с корзиной, составом, упаковками, выбранным ПВЗ, тарифом и сроком действия; устаревший расчёт отклоняется.
- Добавляем расширяемый тип доставки и снимок доставки в заказе, вес и габариты упаковки товара. Для живых расчётов отсутствующие габариты — ошибка, а не выдуманные значения.
- При отсутствии аккаунтов интеграции выключены; тесты используют явные подмены внешних API. Демонстрационные товары сохраняются.
- Существующие тексты и реквизиты сначала исследуются; пользовательские данные и локальные изменения не перезаписываются.
- Не переписывать историю миграций по смыслу; удаление устаревшего названия из описательных строк допустимо. Налоговые коды требуют явного маппинга, а не переименования.

## Testing Decisions

Поведенческие Django-тесты границ checkout/payment/delivery: подмена суммы/ПВЗ, истёкший расчёт, смена корзины, недоступность API, идемпотентность, несовпадение суммы/валюты/заказа, поздняя оплата и возвраты. Существующие тесты, проверка миграций, lint, сборка, браузерные сценарии desktop/mobile с изолированной тестовой БД. Внешние платежи, письма и отправления в проверках не создаются.

## Out of Scope

Публикация на рабочем сервере, обращение в банк от имени продавца, приём реальных платежей, создание реальных отправлений и изменение реального ассортимента. Автоматическая покупка/подключение кассы не входит в задачу. Автоматическое создание накладной требует подтверждённых реквизитов отправителя и отдельного согласованного процесса; пока предусмотреть явный ручной этап после подтверждения оплаты.

## Further Notes

Ответы пользователя: оба сервиса пока подключаются; отправка из Тольятти; накладные СДЭК оформляются вручную; юридический статус продавца, реквизиты и касса пока не определены. Реальную оплату и доставку не включаем. Эти ответы заменяют соответствующие предварительные неизвестные.
