# 02 — Выбор ПВЗ и расчёт доставки СДЭК

Status: done
Blocked by: None

**What to build:** Покупатель выбирает ПВЗ официальным виджетом, сервер проверяет пункт и рассчитывает доставку, итог отображается и сохраняется вместе со снимком доставки при создании заказа.

- [x] Расширяемые способы доставки; вес/габариты упаковки и код тарифа.
- [x] OAuth API v2 и ограниченный серверный proxy виджета.
- [x] Цена, адрес, тариф и срок проверяются сервером; подмена и устаревший расчёт отклоняются.
- [x] Ошибки API, отсутствие настроек, смена корзины/ПВЗ, повторное оформление обработаны.
- [x] Демо-товары сохранены; отсутствие ключей не выдаётся за реальный расчёт.
- [x] Работают формы, мобильная версия и доступные состояния ошибок; поведенческие тесты.

## Comments

Область: orders/, catalog/, cart/, frontend/shop*, отдельный модуль frontend/cdek*, templates/shop/. Новый класс оплаты AlfaBankClient и настройки ALFABANK_* согласуются с основным агентом. Не редактировать payments/, config/, .env.example, core/middleware.py, content/.

2026-10-01: реализовано. Типы static/cdek_pvz, фактические упаковки каждой единицы товара, код тарифа,
снимок доставки в заказе. OAuth/API v2, проверка ПВЗ и ограничений по весу, расчёт в рублях.
Ограниченный proxy принимает только offices, разрешённые фильтры и пагинацию; upstream URL и секреты
не принимаются из браузера. Виджет 3.11.1 выбирает только код ПВЗ; цена и адрес из него не используются.
Подписанный расчёт связан с сессией, корзиной, версией, ценами, упаковками, способом, тарифом, ПВЗ,
режимом API и городом отправителя; ограничен временем. Оформление проверяет его под блокировками БД.
Неизвестная стоимость больше не отображается бесплатной доставкой или окончательным итогом.

Frontend: карта загружается по нажатию, есть ввод кода и расчёт без JavaScript; отмена/поколение
асинхронных запросов, истечение расчёта, Alpine destroy, HTMX замена формы, доступные сообщения.
После выбора карта сворачивается; повторное открытие использует существующий виджет.
Переход на checkout полностью загружает страницу для изолированной политики CSP.
Политика обработки данных отделена от принятия условий покупки. Оплата и тестовые сценарии
переведены на контракт Альфа-Банка. Менеджеру показаны ПВЗ, тариф и ручная накладная после оплаты.

Миграции: catalog 0003; orders 0004 (поля), 0005 (отключение только точного старого
стандартного cdek-pickup/«СДЭК — пункт выдачи по России»/300 ₽). Локальная БД не мигрировалась,
товары и данные владельца не изменялись, реальных API вызовов и отправлений не создавалось.

Проверено: 17 CDEK-тестов; общий запуск orders.test_cdek + orders.test_delivery + orders.tests + cart + catalog:
54 теста успешно, один PostgreSQL-only тест блокировок пропущен на SQLite. Ruff, форматирование,
синтаксис JS проверены. Основной агент провёл desktop/mobile браузерные сценарии с подменённым SDK/API,
финальная сборка и общая проверка находятся у основного агента. Выполнен собственный просмотр изменений
на доверие данным браузера, устаревшие расчёты, блокировки, ошибки провайдера и жизненный цикл UI.

Для реального запуска нужны договор/API СДЭК, подтверждённый код города Тольятти, тариф по договору,
измеренные упаковки, ключ Яндекс.Карт с ограничением домена. Реальные карты/CSP и ответы СДЭК
требуют приёмки после подключения аккаунта; отсутствие ключей не имитируется рабочей интеграцией.
