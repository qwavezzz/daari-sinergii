# Пробный заказ с общей коробкой и рабочим СДЭК

Status: prepared; VPS execution pending

Запрос владельца: создать тестовый заказ, проверить расчёт всей доставки, выбор
коробки и сохранение правильного ПВЗ. Получатель явно выбран: MSK2, Москва,
ул. Международная, 15. Отправитель — настроенный TLT4. Реальных замеров и цен нет.

Проверка: отдельный операторский процесс на VPS вызывает штатные cart/checkout
views с CSRF; рабочий CDEK API считает реальные тарифы по учебным габаритам.
Две отдельные QA-копии товаров доступны только внутри незавершённой транзакции;
после commit остаются скрытыми черновиками с резервом по одной единице.
Исходные профили, их подтверждения, публичные способы доставки и env неизменны.
Цена 50 ₽ на коробку — только в памяти процесса и в снимке тестового заказа.

Ожидается один неоплаченный заказ с пометкой «не отправлять», два письма через
штатную очередь, подписанная стоимость и адрес MSK2 из ответа API. Повтор запуска
не создаёт дубль; смена ПВЗ без перерасчёта и POST без CSRF должны отклоняться.
Ошибки проверки откатывают весь заказ, QA-копии и письма. Отмена выполняется
штатным transition_order и освобождает только резервы этого проверочного заказа.

Это серверная проверка реальных views, не браузерный тест выбора точки на карте.
После выполнения владелец проверяет письмо и страницу заказа на публичном сайте.
Банк, накладные и физическая вместимость этим сценарием не проверяются.

SQLite, 1 проверка видимости из другого PostgreSQL-соединения требует PostgreSQL.
Транспорт СДЭК в локальных тестах подменён, разбор API и выбор цены штатные:
проверка специально делает большую подходящую коробку дешевле меньшей.
