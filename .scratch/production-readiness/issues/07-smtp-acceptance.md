# Приёмка почтовых уведомлений на VPS

Status: in-progress

Разработчик выполняет команды на VPS самостоятельно. SMTP REG.RU уже настроен;
оформление заказа и платёжка остаются выключенными. Рабочие секреты не запрашивать.

Последнее уточнение пользователя: все почтовые адреса уже указаны, при заказах
меняется адрес покупателя. Адреса менеджера/ответов повторно заполнять не требуется.
Оставшаяся внешняя проверка SPF/DKIM/DMARC относится к доставке, а не к смене адресов;
её результат не подтверждён. Текущий приоритет — сохранение проекта в GitHub.

## Подтверждено

- Проверка конфигурации SMTP ранее прошла; на момент исходного аудита очередь была пуста,
  таймер уведомлений присутствовал.
- После восстановления DNS разработчик выполнил `sendtestemail` на VPS и получил
  письмо на свой личный ящик.
- В первый запуск передавался только личный адрес; автоматической копии почте сайта
  `sendtestemail` не отправляет. Затем выполнен отдельный тест на почту сайта,
  разработчик подтвердил его доставку.
- Таймер `active/waiting`, `enabled`; присланный последний запуск — 18.09.2026
  15:02:40 MSK. Служба завершилась тогда же: `Result=success`, `ExecMainStatus=0`.
- Последующая проверка БД: `pending_mail: 0`, `mail_with_errors: 0`.
- В исходнике просмотренного письма REG.RU `Authentication-Results` отсутствует.
  Пользователь сообщил, что имеет только ящики REG.RU; внешняя доставка не проверялась.
- Присланный исходник теста на почту сайта также не содержит `DKIM-Signature`.
  Видимый маршрут — mail1.hosting.reg.ru → sm38.hosting.reg.ru; получатель совпадает
  с отправителем. Не считать это доказательством отсутствия внешней подписи.
- Повторные публичные NS/MX/SPF/DMARC совпали с исходным аудитом;
  артефакт — artifacts/readiness/dns-mail-readiness.json.
- Скриншот Roundcube подтвердил тестовое письмо во «Входящих» ящика сайта.
  Видны также прежние письма о создании/отмене заказа; полный сценарий нового
  релиза по этому списку не подтверждён.
- Пользователь вошёл в DNSadmin и подтвердил, что показанная зона — dari-sinergii.ru.
  Затем прислал значение DKIM TXT с RSA-ключом и DMARC `p=none; aspf=r; sp=none`.
  Затем уточнил имя `dkim._domainkey.dari-sinergii.ru.`. OpenSSL прочитал публичный ключ:
  RSA 2048 бит, DER 294 байта; артефакт — artifacts/readiness/dkim-key-supplied.json.
  Публикация проверена через Google и Cloudflare: оба вернули один TXT с тем же
  ключом; артефакт — artifacts/readiness/dkim-public-dns.json. Использование ключа
  отправляющим SMTP и подпись внешнего письма пока не подтверждены.

## Осталось

- Уточнить папку в личном ящике и результаты SPF/DKIM/DMARC тестового письма.
- Проверить использование опубликованного ключа отправляющим SMTP: результат
  внешнего получателя либо подтверждение настройки почтовой услуги.
  DNS-часть проверена; дополнительных изменений в записи не предложено.
  Отсутствие Authentication-Results
  не трактовать как провал проверок.
- Проверить адрес менеджера и адрес для ответов.
- Не приравнивать `sendtestemail` к проверке полного сценария уведомлений о заказах.
  Отправку реальных сообщений из очереди планировать только после просмотра её состояния.

  вне REG.RU. По RFC 8601 B.1 это не даёт результата проверки валидности письма.
  Запрошены DKIM-Signature и только значения d=/s=; секреты и полное письмо не нужны.
- 2026-09-18: разобран присланный тестовый исходник: оба заголовка отсутствуют.
  Повторно прочитаны публичные почтовые DNS-записи; изменений нет. По официальной
  инструкции REG.RU подготовлен вход в панель услуги через личный кабинет,
  поскольку Roundcube не определяет панель управления и состояние DKIM.
- 2026-09-18: скриншот показывает входящие Roundcube, а не настройки услуги.
  Подготовлен прямой переход в личный кабинет REG.RU для выбора почтовой услуги.
- 2026-09-18: пользователь нашёл DNSadmin с единственной зоной dari-sinergii.ru.
  Дальнейшая диагностика начинается с просмотра её записей; новая зона не создаётся,
  DNS не меняется. Инструкция сведена к одному действию с уже открытой панелью.
- 2026-09-18: пользователь прислал значение DKIM TXT и DMARC. Публичный RSA-ключ
  разобран OpenSSL без ошибок; запрос точного имени записи ожидает ответа.
  Селектор не угадывается, подпись писем не объявлена проверенной.
- 2026-09-18: получено имя dkim._domainkey.dari-sinergii.ru.; Google и Cloudflare
  вернули совпадающий ключ, SHA256 DER 16ad6d516228dc6c48531e1f6d5eb1f26c245569a85e1d320a12243c6c9454d0.
  Диагностика публикации завершена. Подпись внешнего письма остаётся на приёмке;
  параллельно продолжается проверка обновлений ОС (issue 08).
