# Постоянная настройка DNS VPS

Status: done

После временного выбора 1.1.1.1 / 8.8.8.8 обычный HTTPS с VPS успешен. Networkctl
подтвердил DNS и Netplan/networkd на ens3; источник — 50-cloud-init.yaml, DHCP4.
Подготовлены отдельный DNS drop-in, защищённые от перезаписи команды установки,
проверки обоих доменов и инструкция отмены. Значения IP/шлюза и настройки SSH/VPN
не редактируются; применение через reload может временно убрать DHCP-адрес.

Документ: deploy/DNS-PERSISTENCE.md. Шаблон: deploy/systemd-networkd/90-dari-dns.conf.
Установка подтверждена: networkctl показывает drop-in и публичные DNS. После reload
зафиксирован `degraded (configuring)` без IPv4, немедленные DNS-запросы не прошли.
Последующие внешние запросы к обоим `/health/` дали HTTP 200 с 134.0.113.203.
Разработчик подтвердил восстановление: `routable (configured)`, 192.168.0.170/24,
default via 192.168.0.1 и публичные DNS; drop-in остаётся подключённым.
Повтор с VPS прошёл: A-запросы обоих доменов дали 134.0.113.203 с `Data from: network`,
оба HTTPS `/health/` без `--resolve` вернули `status=ok`, HTTP 200 и актуальный IP.
При последующей перезагрузке после обновления ОС сохранение DNS подтверждено:
1.1.1.1 / 8.8.8.8, оба домена разрешаются в 134.0.113.203, оба health HTTP 200.
