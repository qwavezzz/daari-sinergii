## Приоритетные находки

### 1. Не подтверждена фактическая индексация в поисковых кабинетах

**Приоритет: высокий для завершения SEO-приёмки. Тип: непроверенная часть, не ошибка кода.**

По последнему зафиксированному состоянию проекта Google Search Console и
Яндекс Вебмастер не подключены; новых подтверждений или выгрузок нет.
HTTP 200 и отсутствие noindex разрешают индексацию, но не доказывают её.
Запросы `site:` в доступном поисковом инструменте не дали результатов —
по этому нельзя заключать, что в Google или Яндексе проиндексировано ноль страниц.

**Действие:** подтвердить сайт в клиентских аккаунтах, добавить основной
`https://dari-sinergii.ru/sitemap.xml`, проверить главную и несколько материалов
инструментом проверки URL. Сверить выбранные поиском canonical и исключённые страницы.
Инструкция проекта: [SEO-SETUP.md](SEO-SETUP.md).
Порядок подтверждения прав описан в [документации Яндекса](https://yandex.ru/support/webmaster/ru/service/rights).

### 2. Часть отраслевых переходов не соответствует обещанию исходного блока

**Приоритет: высокий для качества посадочных страниц. Влияние: поиск и обращения.**

На главной блоки применения описывают водоподготовку, но некоторые связанные
страницы посвящены другим сценариям:

| Исходный блок на главной | Адрес назначения | Что получает посетитель |
|---|---|---|
| Частные дома: источник воды, анализ, расход | `/materials/family/` | «Домашний уход и wellness», масла, кремы и водные процедуры |
| Сельское хозяйство: мойка продукции, тары, технологические контуры | `/materials/agriculture/` | «Для конных клубов и хозяйств», уход за лошадьми и КРС |
| Спортивные объекты: бассейны, фильтрация и рециркуляция | `/materials/sport/` | Материалы о процедурах и уходе после нагрузки |

**Вывод:** HTML-ссылки исправны, но пользователь, ищущий оборудование для воды,
не получает ожидаемого продолжения темы. Это оценка соответствия содержания,
а не доказанный штраф поисковой системы.

**Действие:** согласовать с клиентом назначение страниц. Для водоподготовки
подготовить релевантные HTML-разделы с задачей объекта, исходными данными,
составом решения и примером применения; существующие материалы по уходу
оставить отдельным направлением. Не заменять страницы массово без карты URL.

### 3. Тематические страницы преимущественно работают как подборки PDF

**Приоритет: высокий для развития органического трафика. Влияние: полнота ответа.**

Видимый текст в основном содержимом восьми тематических страниц составляет
примерно 163–243 словесных токена, включая подписи PDF и общие блоки. Например:

- `/materials/hydrolats/`: 163 токена; краткое введение и документ.
- `/materials/oils/`: 242 токена; несколько вводных абзацев и ссылки на документы.
- `/materials/technology/`: 218 токенов; вводные ограничения и каталог документов.

Это не нарушение нормы количества слов: у Google нет обязательного минимума.
Наблюдаемый недостаток — значительная часть ответа требует открытия PDF,
а HTML-страница мало объясняет собственно продукт, его выбор и применение.
PDF тоже могут индексироваться; утверждение «поисковик их не видит» здесь неверно.

**Действие:** сначала усилить 2–3 действительно приоритетные страницы полезным
самостоятельным HTML-содержимым: назначение, отличие вариантов, реальные
характеристики, ограничения и ответы на вопросы клиента. PDF оставить как
дополнение. Согласованные источники, автора/проверяющего и дату обновления
указывать там, где это оправдано содержанием, особенно для материалов об уходе
и оздоровлении. Не придумывать исследования, отзывы или лечебные свойства.
Подход согласуется с [рекомендациями Google по полезному контенту](https://developers.google.com/search/docs/fundamentals/creating-helpful-content).

Контент и клиентская приёмка ранее отложены пользователем: эти рекомендации
зафиксированы, но работа по ним в данном аудите не возобновлялась.

### 4. Две версии одного PDF не объединены canonical

**Приоритет: средний. Влияние: дубли URL и выбор адреса документа в поиске.**

Проверенная пара:

- `https://dari-sinergii.ru/documents/oil-guide/`
- `https://dari-sinergii.ru/documents/oil-guide/?download=1`

Оба ответа — HTTP 200, `application/pdf`. Байты совпадают:
SHA-256 `e65d16e510cc54475c1f4dc02e2dbd114b0a51b60db312a919d69149cbceae39`.
У обоих отсутствует HTTP `Link` с `rel="canonical"`. Ссылки открытия и скачивания
есть на страницах материалов. Это не означает, что Google уже создал два
результата, но предпочтительный URL сервер не сообщает.

**Действие:** в `content/views.py`, в ответе `document()`, добавлять для обеих
версий заголовок:

```http
Link: <https://dari-sinergii.ru/documents/oil-guide/>; rel="canonical"
```

Адрес формировать из канонического origin и slug документа. Сохранить
`Content-Disposition: attachment` для скачивания, проверки публикации и
защитные заголовки. Для остальных документов проверить тот же сценарий.
HTTP canonical для PDF поддерживается [Google](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls).

### 5. Отсутствует структурированная информация о компании и навигации

**Приоритет: средний. Влияние: понимание сущности компании и представление страниц.**

На всех 10 основных страницах после выполнения JavaScript обнаружено
**0 JSON-LD, 0 microdata и 0 RDFa с vocab/typeof**. Телефон, email и юридическое
имя при этом доступны обычным текстом — контактные данные не отсутствуют.

**Действие:** добавить `Organization` с реальными данными, логотипом и URL
компании на главную; для разделов материалов — согласованный с видимой
навигацией `BreadcrumbList`. Проверять разметку после рендеринга. Не добавлять
вымышленные рейтинги и не размечать библиотечную подборку как экспертную
статью без соответствующего содержания.
См. [Organization](https://developers.google.com/search/docs/appearance/structured-data/organization)
и [BreadcrumbList](https://developers.google.com/search/docs/appearance/structured-data/breadcrumb).

Отсутствие schema не блокирует индексацию, а добавление не гарантирует
расширенный результат. Разметку демотоваров сейчас не требуется выводить
ради поискового продвижения магазина: он сознательно закрыт от индексации.

### 6. Некоторые заголовки недостаточно точно описывают тему

**Приоритет: средний/низкий. Влияние: понятность страницы и поискового сниппета.**

Все title уникальны и заполнены. Однако «Технология и ограничения» не называет
озон, «Для спортивных клубов» не уточняет продукт или задачу, а главный H1
«Озон — сила природы» представляет собой слоган. Подзаголовок главной уже
раскрывает три направления, поэтому это улучшение формулировок, а не отсутствие темы.

**Действие:** уточнять title/H1 по фактическому содержимому и согласованной
карте запросов. Например, для текущей страницы технологии —
«Озон: технология применения и ограничения — Дары Синергии».
Не обещать водоподготовку в title страницы, пока её содержание об уходе.
Короткие description сами по себе не ошибка; увеличивать их только для
полезной конкретики, без доведения до формального числа символов.
См. [title links](https://developers.google.com/search/docs/appearance/title-link)
и [описания сниппетов](https://developers.google.com/search/docs/appearance/snippet).

## Небольшие технические замечания

- На 9 страницах материалов ссылка «Вернуться к сайту» ведёт на `/#return`,
  но элемента `id="return"` нет ни в исходном HTML, ни после рендеринга.
  **Уточнение после чтения кода:** `frontend/shared.js` намеренно использует
  `#return` для восстановления прокрутки. Это не сломанная ссылка и не HTTP 404;
  менять её на `/` без сохранения поведения не нужно. В новом релизе добавлен
  нативный якорь для работы без JavaScript, прежнее восстановление сохранено.
- `http://www.dari-sinergii.ru/` проходит два 301-перехода:
  HTTPS www → HTTPS без www. Лучше один прямой переход на основное зеркало,
  но текущая цепочка короткая и корректно завершается.
- HSTS в проверенных ответах отсутствует. Это ранее известная задача HTTPS,
  а не обнаруженная причина неиндексации; настройку вести отдельно по
  [памятке](CONTINUE-AT-HOME.md), учитывая поддомены.

## План действий

1. **Поисковые кабинеты:** подтвердить права, отправить основной sitemap,
   получить сведения о фактической индексации. Доступы принадлежат клиенту.
2. **Небольшие изменения кода:** HTTP canonical для PDF, нативный якорь для `/#return`,
   `Organization` и `BreadcrumbList` на реальных данных. Затем повторить проверки
   и выпускать отдельным релизом; этот аудит их не устанавливал.
3. **Когда вернёмся к контенту:** согласовать главные запросы/регионы и назначение
   отраслевых страниц, усилить 2–3 приоритетных HTML-страницы, уточнить title/H1.
4. **Измерения:** отдельный мобильный Lighthouse/PSI и данные CWV из поискового
   кабинета; после накопления данных — анализ показов, запросов и обращений.

Общая оценка «SEO из 100» не выставлялась: без поисковых данных, спроса,
конкурентного сравнения и нормированных скоростных измерений она была бы условной.
Ссылочный профиль, реальное количество проиндексированных страниц, позиции,
история трафика и региональный спрос остаются вне подтверждённой части аудита.

## Доказательства и воспроизведение

Локальные артефакты лежат в игнорируемой Git папке `artifacts/seo-20260921/`:

- `skill-source.json`, `skills/seo-audit/SKILL.md` — происхождение методики.
- `public-http.json` — 68 первоначальных HTTP-проверок.
- `variants.json` — 13 дополнительных проверок, цепочки редиректов, хеши PDF.
- `browser.json` — DOM, ссылки, ресурсы, ошибки и одиночные скоростные замеры.
- `navigation.json` — HTMX и загрузка без JavaScript.
- `pages.csv` — метаданные 10 страниц основного sitemap.
- `html/`, `screenshots/` — исходный HTML и 18 снимков viewport.
- `fragment-check.json` — ссылки на отсутствующий `#return`.
- `lazy-image-targets.json` — доступность 8 дополнительных изображений.
- `pagespeed-api.json` — ответ API с ограничением квоты.
- `collect-browser.mjs`, `check-variants.py`, `check-navigation.mjs` —
  использованные дополнительные сборщики, только публичное чтение.

Начальную HTTP-проверку можно повторить существующим скриптом:

```bash
python scripts/audit-public-site.py --output artifacts/seo-recheck/public-http.json
```

Для повторения браузерных сборщиков нужен Playwright и установленный Chromium;
переменная `PLAYWRIGHT_CHROMIUM_EXECUTABLE` указывает на его исполняемый файл.
Артефакты не содержат авторизованных сессий или серверных секретов; в Git не
добавлялись. Этот отчёт сохраняется в проекте отдельно от временных измерений.
