# Тестовая оплата и письма

Ключи и пароль отправителя не входят в репозиторий. Локальные команды читают
`var/local-settings.json` только при `config.settings_dev`. В production используются
переменные окружения из `/etc/dari/dari.env`; тесты не читают локальный файл.
Переменные окружения имеют приоритет. После изменения файла перезапустите `runserver`.

## Получить тестовый магазин ЮKassa

1. Зарегистрируйтесь в [ЮKassa и выберите тестирование платежей](https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing).
   На этом этапе реквизиты компании и договор не требуются.
2. В тестовом магазине откройте «Интеграция → Ключи API». Выпустите секретный ключ.
3. В `var/local-settings.json` заполните `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY`.
   Оставьте `YOOKASSA_TEST_MODE: true`. Это реальные доступы к тестовой среде, их нельзя публиковать.
4. Выполните `python manage.py check_integrations --only payments`.
   Проверка читает настройки магазина через API, сверяет его номер и тестовый режим, не создавая платежей.

Пример локального файла (значения доступа нужно заменить):

```json
{
  "CHECKOUT_ENABLED": true,
  "YOOKASSA_ENABLED": true,
  "YOOKASSA_TEST_MODE": true,
  "YOOKASSA_SHOP_ID": "",
  "YOOKASSA_SECRET_KEY": "",
  "EMAIL_BACKEND": "django.core.mail.backends.smtp.EmailBackend",
  "EMAIL_HOST": "smtp.yandex.ru",
  "EMAIL_PORT": 465,
  "EMAIL_USE_SSL": true,
  "EMAIL_USE_TLS": false,
  "EMAIL_HOST_USER": "",
  "EMAIL_HOST_PASSWORD": "",
  "DEFAULT_FROM_EMAIL": ""
}
```

Перед созданием каждого платежа приложение проверяет магазин через `/v3/me`.
Рабочие ключи в тестовом режиме отклоняются до запроса на создание платежа.
Сумма, валюта, магазин, номер заказа и признак тестирования повторно проверяются при подтверждении.
Признак `test` сверяется также с сохранённым режимом самого заказа. Старые заказы другого
режима не участвуют в фоновой сверке и не могут оплачиваться с новыми настройками.

Реализован сценарий оплаты банковской картой на странице ЮKassa: `bank_card`, `redirect`,
`capture=true`. Данные карты вводятся у провайдера. Отдельного тестового API-адреса или
параметра `test` в запросе создания не нужно — среду определяют ключи магазина.
[Описание сценария](https://yookassa.ru/developers/payment-acceptance/getting-started/quick-start).

## Подключить отправку писем

Для отправки нужен почтовый ящик с SMTP. Адрес получателя сам по себе не даёт права отправлять письма от его имени.
Для Яндекса разрешите почтовые программы в настройках ящика и создайте пароль приложения
для почты в Яндекс ID. [Официальная инструкция](https://yandex.ru/support/yandex-360/customers/mail/ru/mail-clients/others).

- `EMAIL_HOST_USER` — логин ящика-отправителя.
- `EMAIL_HOST_PASSWORD` — пароль приложения, не основной пароль Яндекс ID.
- `DEFAULT_FROM_EMAIL` — полный адрес этого же ящика.
- SSL: `smtp.yandex.ru`, порт `465`, `EMAIL_USE_SSL=true`, `EMAIL_USE_TLS=false`.

В админке откройте «Настройки магазина → Почта менеджера по продажам» и сохраните получателя.
Новый адрес используется для новых событий. Уже поставленные в очередь письма сохраняют первоначального адресата.
Пустое поле использует старую серверную настройку `MANAGER_EMAIL`, если она задана.

```powershell
python manage.py check_integrations --only email
python manage.py check_integrations --only email --send-test-email
```

Первая команда только проверяет SMTP; вторая отправляет одно проверочное письмо менеджеру.
Успешный ответ SMTP означает принятие письма сервером. Подтвердите получение во «Входящих» или «Спаме».

## Проверить весь заказ

1. Используйте отдельную локальную базу или демонстрационный стенд с вымышленными данными.
   Тестовый заказ проходит резервирование и списание остатков для проверки сценария магазина,
   поэтому не тестируйте его на реальных складских остатках и не выдавайте по нему товар.
2. В админке подготовьте тестовый товар с ценой и остатком, способ получения и явно тестовые условия магазина.
   В «Настройках магазина» включите оформление. Не публикуйте тестовые условия как документы реального бизнеса.
3. Запустите `python manage.py runserver`. В локальном режиме он проверяет платежи и очередь писем каждые 15 секунд.
   На VPS эти задачи выполняют поставляемые systemd-таймеры.
4. Оформите заказ: покупатель и менеджер должны получить разные письма о создании.
5. Оплатите тестовой картой из таблицы ниже. Возврат на сайт сам по себе не подтверждает оплату:
   используется проверка API, локальная фоновая сверка или кнопка обновления статуса на странице заказа.
6. Убедитесь, что заказ стал «Оплачен», менеджер получил «Ожидает сборки», а покупатель — подтверждение оплаты.
7. Повторная проверка платежа не должна повторно списывать остаток или создавать новые письма.
8. Проверьте отказ оплаты и временную ошибку почты. Неотправленные письма остаются в очереди.

Для ручной проверки используйте тестовые карты из [документации ЮKassa](https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing):

| Сценарий | Тестовый номер | Ожидаемый результат |
| --- | --- | --- |
| Успех без 3-D Secure | `5555 5555 5555 4444` | Заказ оплачен, два письма об оплате |
| Успех с 3-D Secure | `5555 5555 5555 4477` | После подтверждения заказ оплачен |
| Недостаточно средств | `5555 5555 5555 4600` | Заказ отменён, резерв освобождён, писем об успешной оплате нет |

Укажите будущий срок действия, произвольный трёхзначный CVC и произвольные цифры для 3-D Secure.
Настоящую карту не используйте. После отмены оформите новый заказ для следующего сценария.
СБП и другие способы оплаты этими проверками не покрываются.

На публичном HTTPS-сервере зарегистрируйте в тестовом магазине URL
`https://<домен-демостенда>/payments/yookassa/test/webhook/` и события `payment.succeeded`,
`payment.canceled`, `payment.waiting_for_capture`, `refund.succeeded`.
Этот адрес работает только при `YOOKASSA_TEST_MODE=true`.
Для рабочего магазина используется отдельный URL `/payments/yookassa/webhook/` только при
`YOOKASSA_TEST_MODE=false`. Если тестовый магазин был настроен на старый общий URL, замените его.
Для HTTP-уведомлений нужны HTTPS, порт 443 или 8443 и TLS не ниже 1.2.
ЮKassa не может присылать webhook на `localhost`; локальную демонстрацию обслуживает сверка через API.
[Документация уведомлений ЮKassa](https://yookassa.ru/developers/using-api/webhooks).

Журнал отправки находится в «Email-уведомлениях». Письма содержат текстовую и HTML-версии.
При ошибке отправка повторяется с тем же Message-ID. SMTP не гарантирует отсутствие дубля при аварии
между приёмом письма сервером и записью результата в базу.

Новые заказы сохраняют признак тестирования; их письма помечаются `[ТЕСТ]`, даже если позже настройки изменятся.
Старые записи до этой миграции не получают автоматически тестовую метку — перед запуском их нужно проверить.
Перед переходом к рабочим ключам завершите тесты и разберите оставшиеся тестовые заказы/письма.
Рабочий режим по-прежнему требует согласованной фискализации и отдельного разрешения запуска.
Вопрос чеков для платной доставки остаётся отдельной задачей перед реальными продажами.

## Что проверено автоматически

`python manage.py test apps.payments apps.orders.test_notifications --settings=config.settings_test`
проверяет HTTP-запросы с подставными ответами ЮKassa и очередь писем. Проверяются создание,
успех, отказ, повтор уведомления, уведомление до ответа на создание, временная недоступность,
повтор с тем же ключом и ограничение его срока, возвраты и разделение тестовых/рабочих заказов.
Статус `waiting_for_capture` не считается завершённой оплатой.

Это не подтверждает доступ к настоящему тестовому магазину, прохождение 3-D Secure или доставку SMTP.
Для этого нужны ключи/почта и ручной сценарий выше. `check_integrations --only payments`
проверяет только авторизацию и режим магазина, не создаёт и не оплачивает платёж.

По умолчанию `YOOKASSA_RECEIPT_MODE=unconfigured`, поэтому проверка карты не проверяет чеки.
Для проверки товарных чеков через стороннюю онлайн-кассу настройте её тестирование в кабинете
ЮKassa, задайте `YOOKASSA_RECEIPT_MODE=provider` в окружении и согласованные ставки НДС товарам.
В тестовом режиме ЮKassa не отправляет настоящий фискальный чек покупателю; письма нашего
магазина отправляются отдельно и не заменяют чек.
[Тестирование чеков](https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing#receipts).
