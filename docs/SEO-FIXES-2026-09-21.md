навигации и контента. Рабочая БД клиента в ходе разработки не использовалась.
После сообщения разработчика об установке новые SEO-механизмы подтверждены

- Главная, `/materials/water-systems/`, `/materials/oils/`,

- На главной есть валидный JSON-LD Organization; на проверенных страницах

- Sitemap содержит 11 информационных URL, включая новую страницу о воде.
- Магазин отдаёт `noindex, nofollow` в HTML и HTTP-заголовке.
- Оба варианта PDF `oil-guide` возвращают 200 и одинаковый canonical через GET.
  HEAD возвращает 405: исправлена команда проверки в инструкции, переустановка
  из-за этого не требуется.
- HTTP www перенаправляет сразу на HTTPS основного домена, сохраняя путь и параметры.

Свидетельства: `artifacts/seo-20260921/post-deploy.json` (локальный артефакт).
Эти проверки подтверждают публичное поведение; они не заменяют вход в админку
и данные поисковых кабинетов. Архив релиза после установки не пересобирался.

## Что изменено

- **Канонические адреса PDF.** Обычная загрузка, скачивание и URL с параметрами
  отдают один HTTP `Link` с `rel="canonical"`. Проверки публикации и закрытое
  хранение документов сохранены.
- **Organization на главной.** Данные берутся из редактируемых настроек компании;
  пустые контакты не включаются. Нет вымышленных отзывов, рейтингов или адресов.
- **BreadcrumbList и видимые хлебные крошки.** На страницах материалов доступны
  пользователям и поисковикам. Разметка присутствует в серверном HTML и правильно
  меняется при HTMX-переходах и возврате назад.
- **Безопасный JSON-LD.** Символы HTML экранируются; динамическое обновление через
  `textContent`. Проверен ввод с закрывающим тегом `script`. Исполнение скриптов
  из HTMX-фрагментов не включается.
- **Страница `/materials/water-systems/`.** Подбор, состав системы, исходные
  данные, монтаж и ссылка на декларацию оборудования. Ссылки из исходных отраслевых
  блоков о воде ведут на неё. Использованы сведения проекта; цены, точные параметры,
  результаты испытаний и кейсы не придуманы. Иллюстрация сохраняет подпись
  «Концептуальная визуализация».
- **Материалы о маслах, гидролатах и технологии.** Расширены основные HTML-тексты;
  уточнены заголовки отраслевых материалов и description главной. PDF остаются
  дополнительными материалами, а не единственным содержанием страницы.
- **Возврат на главную.** Аудит уточнён: `#return` уже обрабатывался JavaScript
  для восстановления прокрутки. Существующее поведение сохранено, добавлен
  обычный HTML-якорь для работы без JavaScript.
- **Редирект HTTP www.** Конфигурация Nginx ведёт сразу на HTTPS основного домена,
  сохраняя путь и параметры; ACME-проверка остаётся доступна.
- **Демоверсии.** Магазин и GitHub Pages остаются закрытыми от индексации.
  Production JSON-LD не попадает в статическую демонстрацию с тестовыми доменами.

## Как сохраняются изменения клиента

Команда `manage.py apply_seo_content` по умолчанию только показывает план.
Запись требует `--apply`; штатный `deploy/release.sh` запускает её после бэкапа.

Старые тексты и ссылки обновляются лишь при совпадении с исходным импортом.
Переименованные страницы, черновики, изменённые секции, редакторские записи и
занятые адреса пропускаются. Повторный запуск не пересоздаёт применённые секции.
Новая страница создаётся в CMS и дальше редактируется обычным способом.

После установки разделы, отмеченные в выводе как «ПРОПУСК», могут сохранять прежний
текст. Это нужно проверить по содержанию, без принудительной перезаписи.

## Проверки

- Django: **88 тестов — 87 успешно, 1 пропущен**. Пропущена проверка конкурентного
  доступа, требующая PostgreSQL; локальный прогон использует SQLite.
- Шесть новых серверных тестов покрывают canonical PDF, доступ к черновикам,
  экранирование JSON-LD, смену slug, noindex, просмотр без записи, идемпотентность,
  сохранение клиентского текста и конфликты адресов.
- JavaScript: **4 теста успешно**.
- Playwright: **14 из 15 успешно в общем прогоне**; старый длинный сценарий
  оформления заказа вышел за общий лимит 30 секунд. Он прошёл отдельно за 11,6 с
  с лимитом 60 секунд, без изменения проверок или кода магазина.
- Все три новых SEO-сценария прошли: HTMX/история, ширины 1440/390/320,
  серверный HTML без JavaScript и закрытый от индексации магазин.
- Просмотрены скриншоты новой страницы и обновлённых материалов на телефоне и
  компьютере; горизонтального переполнения и ошибок JavaScript не обнаружено.
- Ruff и проверка отсутствия новых миграций пройдены. Production frontend и
  статическая демонстрация Pages собираются.
- Демонстрация Pages: 47 страниц, 16 демотоваров; проверены desktop/mobile,
  встроенный Android-браузер, навигация, PDF, локальная корзина и режим без JS.
  Первый запуск штатной проверки остановился из-за POST-запросов внедрённого
  антивирусом скрипта. В локальной копии проверяющего скрипта исключён только
  `gc.kis.v2.scr.kaspersky-labs.com`; все проверки сайта сохранены и прошли.
  Рабочий проверяющий скрипт и настройки антивируса не менялись.
- Проверен синтаксис Bash-скрипта выпуска и всех блоков команд инструкции.

## Что ещё требует VPS или аккаунтов клиента

1. Разработчик сообщил об установке; публичное поведение проверено выше.
   Самостоятельно проверить вход в админку и содержание отредактированных страниц.
   Повторять [установку](../deploy/INSTALL-SEO-20260921.md) не нужно.
2. Подтвердить домен в Google Search Console и Яндекс Вебмастере, передать sitemap
   основного сайта. Инструкция и готовые SEO-механизмы уже есть в
   [SEO-SETUP.md](SEO-SETUP.md); пароли или коды подтверждения не выдумываются.
3. После обхода смотреть реальные запросы, индексирование и полевые Core Web Vitals.
   Прохождение автоматических тестов не подтверждает позиции или включение в индекс.
4. При появлении исходных данных дополнить сайт реальными характеристиками,
   фотографиями производства, кейсами и согласованной географией работы.

Проверка продления SSL, настройка HSTS, мониторинг и ответственный за сопровождение
остаются отдельными эксплуатационными задачами из [памятки](CONTINUE-AT-HOME.md).
Оплата и доставка в этом выпуске не дорабатывались.
