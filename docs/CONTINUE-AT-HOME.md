## Как продолжить с другого компьютера

В существующей чистой копии репозитория выполнить `git pull --ff-only` на ветке main.
Если есть домашние незакоммиченные изменения, сначала сохранить их; не использовать
reset --hard для синхронизации. Для новой копии:

```bash
git clone https://github.com/qwavezzz/daari-sinergii.git
```

Для локального запуска следовать [README](../README.md). GitHub не содержит рабочую
БД и загруженные клиентом файлы. Production использует `/etc/dari/dari.env`;
пустой `.env.example` является только шаблоном.

Секреты, заполненный `private-handoff/CLIENT-ACCESS.md`, скачанные бэкапы,
браузерные профили, кэши и временные сборки в Git не отправляются. Нужные приватные
файлы перенести между компьютерами отдельно через защищённое хранилище.

Приложение в readiness-релизе уже развёрнуто. Часть эксплуатационной документации
и улучшение повторов HTTP-проверки в `deploy/release.sh` сделаны после сборки
архива; GitHub push сам по себе не устанавливает их на VPS. Workflow main запускает
CI и публикацию демонстрации GitHub Pages, а Django развёртывается отдельно.
Старый архив readiness с прежним именем не пересобирать и установку вслепую не повторять.
