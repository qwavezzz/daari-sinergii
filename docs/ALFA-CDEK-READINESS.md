# Подготовка магазина к Альфа-Банку и СДЭК

Обновлено 1 октября 2026 года. Локальный магазин открыт для полного пробного заказа: демо-каталог → выбор ПВЗ → запрос стоимости в официальный тестовый API СДЭК → заказ → заглушка оплаты с успехом, отменой и повтором. Это уже работающий учебный путь; подключение рабочего договора и реальных списаний выполняется отдельно.

## Попробовать сейчас

Локальная база подготовлена, все 16 демо-товаров сохранены. Запуск из корня проекта:

```powershell
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000 --settings=config.settings_dev
```

Открыть `http://shop.localhost:8000/`. Добавить товар, перейти к оформлению, найти город, выбрать ПВЗ. Сумма обновится автоматически; кнопка переведёт на пробную оплату. Денежных списаний, писем покупателям и накладных этот режим не создаёт. Пробные заказы и их результаты видны в админке отдельно от финансового статуса; такие заказы впоследствии нельзя отправить в Альфа-Банк.

`settings_dev` включает `CHECKOUT_ENABLED`, `PAYMENT_STUB_ENABLED`, тестовый СДЭК и публичную тестовую учётную запись из [официального модуля СДЭК](https://github.com/cdek-it/wordpress/blob/main/src/Config.php). Собственные ключи имеют приоритет; рабочий режим никогда не получает публичные тестовые ключи автоматически. Для реального СДЭК нужны свои `CDEK_CLIENT_ID`, `CDEK_CLIENT_SECRET`, `CDEK_TEST_MODE=false`; заглушку оплаты можно оставить включённой для проверки. Серверные секреты не передаются в браузер.

Выбор ПВЗ списком работает без Яндекс.Карт. Для встроенной официальной карты требуется `CDEK_YANDEX_API_KEY` с разрешёнными доменами и подключёнными JavaScript API и API Геокодера: [инструкция СДЭК](https://cdek-it.github.io/wordpress/yandex/). Проверка списка и расчёта не заменяет проверку карты с этим ключом.

Для повторной подготовки локальной SQLite после миграций: `manage.py setup_working_checkout --settings=config.settings_dev`. Команда отказывается работать с production, PostgreSQL, включённым банком или рабочим СДЭК. Она включает учебную доставку с тарифом 136 (ПВЗ–ПВЗ), заполняет только отсутствующую упаковку товаров `DEMO-` и сохраняет редакторские тексты. Принято для обучения: одна упаковка на штуку, 400 г, 20 × 10 × 10 см. Это **не измерения реальной продукции**. Тариф предполагает сдачу в ПВЗ; забор курьером требует другого тарифа.

Отдельная проверка официального API без отправления: `manage.py check_cdek_connection --settings=config.settings_dev`. Проверены Тольятти (431), Москва (44), ПВЗ MOS4. Для учебной посылки API вернул `delivery_sum=210`, `total_sum=252`; сайт использует именно полную `total_sum`, чтобы не потерять налоги/доплаты. Тестовые цены не подтверждают стоимость по вашему будущему договору.

## Перед повторной заявкой в банк

Альфа-Банк требует разместить непосредственно на страницах сайта описание товаров с ценой, характеристиками, комплектацией и гарантийными условиями, контакты и сведения о продавце, а также условия доставки. Ссылки и страницы должны работать, страницы магазина — находиться в согласованном домене. Логотипы банка и платёжных систем на текущей странице требований обозначены как необязательные. Это условия проверки ресурса, а не обещание одобрения. [Требования Альфа-Банка](https://alfabank.ru/sme/payservice/internet-acquiring/docs/process/requirements/).

На двух доменах предусмотрены HTML-страницы `/legal/privacy/`, `/legal/terms/`, `/delivery-and-payment/`, `/returns/`, `/contacts/`, `/product-documents/` и `/faq/`. До заявки необходимо заполнить продавца и неизвестные условия, просмотреть страницы глазами покупателя и проверить карточки товаров. Декларации относятся только к продукции в их области действия и не подтверждают лечебные свойства или одобрение банка.

Демо-позиции остаются для обучения. Перед реальными продажами проверить ассортимент, реальные остатки, цены, описание, маркировку и документы; демонстрационные позиции снять с публичной продажи, сохранив в базе. Отдельно проверить, что страницы политики, заказа и оплаты доступны на том домене, который указан в договоре с банком. Не менять рабочие ключи или режимы ради демонстрации банку неподготовленного магазина.

## Обновление документов без потери редакторских изменений

Тексты сайта хранятся в БД. Изменение JSON в репозитории само по себе не обновляет опубликованные документы. При проверке локальной БД семь страниц и 12 ответов совпадали с прежней поставкой; это наблюдение не гарантирует такого же состояния сервера.

Сначала после применения миграций выполнить предпросмотр:

```console
python manage.py setup_customer_pages --refresh-defaults --dry-run
```

Он не записывает данные. После проверки плана и резервной копии применить:

```console
python manage.py setup_customer_pages --refresh-defaults
python manage.py check_store_readiness
```

Обновляются пустые поля и только точные совпадения с прежними стандартными текстами: они распознаются по контрольным суммам. Изменённые редактором тексты команда оставляет и перечисляет для ручной проверки. Порядок и видимость существующего FAQ, контакты, реквизиты, настройки оформления и существующие способы доставки сохраняются. Новая доставка СДЭК создаётся выключенной; цена для неё поступает из расчёта, нулевое служебное поле цены не означает бесплатную доставку. Без `--refresh-defaults` команда заполняет лишь пустые страницы и первоначальный FAQ.

В сохранённых редакторских текстах вручную проверить наименование банка, фиксированные обещания стоимости СДЭК, готовность кассы и сведения о продавце. Отдельно просмотреть старые принятые условия в архиве заказов: это исторические записи, их нельзя переписывать под новую редакцию. Обновление локальной БД и публикация на рабочем сервере — отдельные операции; применяйте команды только к выбранному окружению после резервной копии.

## Персональные данные и согласия

Для данных, необходимых для заключения и исполнения заказа по инициативе покупателя, предусмотрено договорное основание обработки — пункт 5 части 1 статьи 6 № 152-ФЗ. Политика описывает состав данных, цели, получателей, права и сроки хранения. Принятие условий покупки не должно называться согласием на рекламу или любое использование данных. Если выбрана отдельная цель на основании согласия, нужны самостоятельный текст согласия и отдельное действие пользователя; с 1 сентября 2025 года согласие отделяется от других подтверждаемых документов. [№ 152-ФЗ, официальный текст](https://www.kremlin.ru/acts/bank/24154), [№ 156-ФЗ от 24.06.2025, официальная публикация](https://publication.pravo.gov.ru/document/0001202506240021).

Для запуска владелец подтверждает реального оператора, договоры с банком, СДЭК, хостингом, почтой и кассовым сервисом, место хранения данных и обязанность уведомления Роскомнадзора. Не утверждать, что уведомление подано или базы локализованы, пока это не проверено. Указать фактически выбранные кассовый сервис и ОФД в политике. В текущем тексте их названия оставлены как нерешённая часть подготовки. [Портал персональных данных Роскомнадзора](https://pd.rkn.gov.ru/).

Расчёт доставки использует маршрут, ПВЗ и упаковки; необходимые контакты получателя передаются СДЭК при оформлении отправления. Карта подключает сервисы СДЭК и Яндекс Карт, получающие технические сведения браузера. Платёжные реквизиты карты вводятся у банка. Собирать копии паспорта, защитные коды карты и банковские пароли для обычного заказа или типового возврата не следует.

## Чеки и возврат денег

Определить с бухгалтером кассу, ОФД, налоговую систему, признаки предмета и способа расчёта и ставки НДС каждой позиции, включая доставку. Обычно при предоплате и последующей передаче товара различаются соответствующие чеки; применимость исключений нужно подтвердить для конкретного продавца. Проверять доставку электронного чека покупателю и чеки возврата. [Разъяснение ФНС для интернет-магазинов](https://www.nalog.gov.ru/rn50/news/activities_fts/16201227/).

Также проверить в кассовой интеграции признак расчёта в интернете, адрес сайта и контакт покупателя: ФНС разъяснила эти реквизиты для онлайн-расчётов с 1 сентября 2025 года. Подтвердить результат по реальному тестовому чеку выбранной кассы, а не по факту отправки заказа в банк. [ФНС о реквизитах интернет-чека](https://www.nalog.gov.ru/rn05/news/activities_fts/16547366/).

В документах сохранены дистанционные права: отказ до передачи, семь дней после неё при соблюдении условий качества, три месяца при отсутствии письменных правил возврата в момент доставки. Возврат денег — в законный срок; отсутствие чека не исключает других доказательств покупки. Сохраняется возможность дистанционного возврата подходящим способом, без общего запрета на всю косметику. [Роспотребнадзор, 18.03.2026](https://zpp.rospotrebnadzor.ru/news/federal/572363), [способы возврата, 21.05.2026](https://zpp.rospotrebnadzor.ru/news/federal/574244).

Передать покупателю письменные правила возврата вместе с заказом. Отдельно согласовать порядок претензий по недостаткам. Банковский возврат и фискальный чек возврата — разные действия; исполнитель должен контролировать оба. Не копировать из примерного текста банка условие о 21 рабочем дне или обязательной копии паспорта как универсальное ограничение законных прав покупателя.

## Ручная накладная после оплаты

1. Проверить подтверждённую оплату в заказе и сведения банка. Возврат браузера с платёжной страницы не подтверждает платёж.
2. Взять сохранённые в заказе код и адрес ПВЗ, тариф, сумму доставки и контакты получателя. Сверить реальные упаковки.
3. В кабинете СДЭК оформить накладную от подтверждённого отправителя. Покупатель уже оплатил товары и доставку магазину: не назначать ему наложенный платёж за товары и повторную оплату перевозки. Плательщика услуг выбрать по договору продавца со СДЭК.
4. При отличии фактической стоимости или невозможности отправки остановиться и согласовать решение с покупателем. Не списывать доплату автоматически и не менять молча согласованный итог заказа.
5. Передать отправление, сохранить номер накладной в учёте и сообщить его покупателю. Проверить необходимый чек передачи товара по выбранной кассовой схеме.

Выбор ПВЗ и цена на сайте не создают накладную. Задать ответственного и порядок контроля оплаченных, но ещё не отправленных заказов. [Официальный виджет СДЭК](https://github.com/cdek-it/widget), [документация API СДЭК](https://developer.cdek.ru/).

## Условия включения

До готовности сохранять `CHECKOUT_ENABLED=false`, `ALFABANK_ENABLED=false`, `CDEK_ENABLED=false`; тестовые режимы не считать рабочими. После подключения провести тесты с разрешёнными банком и перевозчиком тестовыми данными, проверить письма, чек, отказ платежа, повторное нажатие оплаты, изменение корзины, недоступность расчёта и возврат. Условия запуска и параметры описаны в `.env.example` и документации развёртывания.

Проверка `check_store_readiness` выявляет заполненность и технические ограничения. Она не подтверждает достоверность реквизитов, согласование договора, достаточность правовых оснований обработки или одобрение банка. Реальные платежи включаются отдельно после решения владельца и завершения подключения.
